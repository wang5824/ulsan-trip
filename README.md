# 울산, 나의 여행

두 단계 설문으로 울산 여행 코스를 추천하는 웹 서비스입니다. 1단계 **암각화 여행자 유형검사**(상황 질문 12개)로 반구천의 암각화 모티프 16유형 중 나의 유형과 여행 취향을 정하고, 2단계 **코스 설계**(6개 질문)에서 동행·지역·이동수단·시간을 더해 관광지와 주변 음식점·카페를 방문 순서대로 추천합니다.

현재 저장소의 정적 장소 데이터와 규칙 기반 점수 계산으로 동작합니다. 별도의 데이터베이스 서버나 생성형 AI API는 사용하지 않습니다.

## 주요 기능과 화면 흐름

| 경로 | 화면 | 주요 기능 |
| --- | --- | --- |
| `/` | 서비스 소개 | 두 단계 흐름 안내, 유형검사 시작 |
| `/test` | 1단계 유형검사 | 상황 질문 12개(2지선다), 선택 즉시 다음 질문, 이전 질문 이동 |
| `/type/[코드]` | 유형 결과 | 유형 그림·설명, 축별 응답 비율, 궁합, 결과 링크 복사, 코스 만들기 진입 |
| `/types` | 16유형 도감 | 전체 유형, 성향 선택으로 유형 찾기, 유형 결정 규칙 |
| `/survey` | 2단계 코스 설계 | 동행인 → 희망 지역 → 이동수단 → 여행 시간 → 음식 선호 → 필수 방문 장소(선택) |
| `/result` | 추천 결과 | 내 유형 카드, 코스 요약, 장소별 추천 이유, 방문 일정, 카카오 지도 |

유형검사를 하지 않은 상태로 `/survey`에 들어오면 유형검사부터 안내합니다. 2단계 설문은 여행 취향을 다시 묻지 않고, 유형검사에서 계산한 활동량·휴식 빈도·관심사·유명도 취향을 그대로 사용합니다. 마지막 단계에서 필수 장소의 지역·시간 충돌을 확인하며, 시간 수정 버튼으로 해당 질문으로 돌아갈 수 있습니다.

`/type/[코드]`는 16개 유형 모두 정적 페이지로 만들어져 결과 링크를 공유할 수 있습니다. 다른 사람의 결과 링크로 들어오면 ‘나도 검사하기’ 버튼이 보입니다.

유형검사 결과와 코스 프로필은 `TravelProvider`가 관리하며 브라우저 `sessionStorage`에 저장해 같은 탭에서는 새로고침해도 유지됩니다. 탭을 닫으면 사라지고, 로그인이나 서버 저장은 없습니다. 저장소를 쓸 수 없는 환경에서는 메모리 상태만 사용합니다. 유형검사를 다시 하면 이전 코스 결과는 지워집니다.

## 개발 환경 실행

Node.js 20.9.0 이상과 npm이 필요합니다.

### 1. 의존성 설치

프로젝트 루트에서 실행합니다.

```bash
npm ci
```

### 2. 지도 환경 변수 설정

프로젝트 루트의 `.env.local`에 카카오맵 JavaScript 앱 키를 설정합니다.

```dotenv
NEXT_PUBLIC_KAKAO_MAP_KEY=발급받은_카카오_JavaScript_앱_키
```

이 변수는 브라우저에서 지도 SDK를 불러올 때 사용합니다. 지도 키가 없거나 SDK 로딩에 실패해도 설문과 추천 일정은 사용할 수 있으며, 지도 영역에 오류 안내와 재시도 버튼이 표시됩니다. 환경 변수를 변경한 뒤에는 개발 서버를 다시 시작합니다. `.env.local`은 Git 추적 대상에서 제외되어 있습니다.

### 3. 개발 서버 시작

```bash
npm run dev
```

브라우저에서 `http://localhost:3000`에 접속합니다.

### 4. 배포용 빌드와 실행

```bash
npm run build
npm run start
```

지도 키는 빌드 전에 설정합니다. 현재 레이아웃은 `next/font/google`로 Gowun Batang·IBM Plex Sans KR 글꼴을 사용하므로 빌드 환경에서 글꼴 다운로드에 필요한 네트워크 접근이 필요할 수 있습니다.

## 장소 데이터

관광지·음식점·카페를 각각 독립된 TypeScript 파일에서 관리합니다. `src/data/places.ts`는 세 목록을 `placeCatalog`로 연결하는 진입점입니다.

| 구분 | 파일 | 등록 수 | 대표 장소 |
| --- | --- | --- | --- |
| 관광지 | [attractions.ts](src/data/attractions.ts) | 211개 | 대왕암공원, 태화강국가정원, 간절곶, 장생포고래문화마을, 외고산옹기마을, 울산대공원, 반구대 암각화 |
| 음식점 | [restaurants.ts](src/data/restaurants.ts) | 238개 | 함양집 본점, 언양기와집불고기, 미진돌곱창 |
| 카페 | [cafes.ts](src/data/cafes.ts) | 82개 | 농도, 라메르판지, 오보드나타, 스매쉬커피, 올리브맨션, 카페 일산지 |

장소에는 고유 ID, 이름, 유형, 카테고리, 주소, 지역(`district`), 위도·경도, 설명, 유명도(`popularityScore`), 활동량, 동행 유형별 적합도, 휴식 적합도, 실내 여부, 권장 체류 시간, 관광두레 여부를 저장합니다. 점수 항목은 1~5점이며 체류 시간은 분 단위입니다. 상세 타입은 [travel.ts](src/types/travel.ts)에 정의되어 있습니다.

장소를 추가할 때는 해당 유형의 파일에 등록하고 전체 목록에서 중복되지 않는 ID를 지정합니다. 주소·지역·좌표·실내 여부·관광두레 여부를 확인하지 못한 경우에는 `null`을 사용합니다. `isTourismDure`가 `true`인 경우에만 가점을 주고, `null`은 화면에 미확인으로 표시합니다. 유명도는 1~5점의 초기 편집 평가를 입력하며, 지역은 주소에서 확인한 구·군을 저장합니다.

기존 490곳에 제공된 블로그 4개와 공유 장소 링크에서 확인한 카페 41곳을 추가해 총 531곳입니다. 여러 글에 반복해서 나온 카페는 합치고 서로 다른 지점은 따로 등록했습니다. 기존 490곳의 ID와 입력되어 있던 좌표 150쌍은 유지했습니다.

2026-10-05에 소상공인시장진흥공단 상가(상권)정보(2026년 6월 30일 기준), 울산광역시 관광 홈페이지, 한국관광공사 대한민국 구석구석, 전국관광지정보표준데이터를 대조해 빈 좌표 333쌍을 보완했습니다. 현재 좌표 확인은 483곳, 미확인은 48곳(관광지 33·음식점 8·카페 7)이며 주소 미확인은 16곳입니다. 추가된 카페 41곳 중 37곳에 좌표가 있습니다. 장소 객체에는 출처 링크를 추가하지 않았습니다.

상업 시설은 상호·지점명과 주소를 대조했고, 상호가 일치하지 않아도 동일한 도로명·건물번호 또는 지번의 공공 좌표가 모두 일치하는 경우에는 해당 주소의 대표 좌표를 사용했습니다. 이 주소 좌표는 매장 출입구나 현재 영업 중인 사업자를 확인했다는 뜻이 아닙니다. 관광지는 공식 관광 자료의 대표 지점을 사용하며, 산·공원·산책로의 입구나 주차장 위치를 보장하지 않습니다. 실제 주행 경로를 측정한 자료가 아닙니다. 확인하지 못한 좌표는 `null`을 유지하고 지도·경로 추천 대상에서 제외하되 장소 데이터는 보존합니다.

수집 범위는 지자체 관광 홈페이지의 공개 목록과 제공된 카페 링크입니다. 인스타그램 게시물은 로그인 제한으로 미포함입니다. 현재 영업·운영 상태를 개별 확인한 자료는 아닙니다. 카페는 남구·중구·북구·동구·울주군에 걸쳐 추가했으며 기존 카페와 링크에 명시된 프랜차이즈 지점을 함께 보존했습니다. 신규 카페의 유명도는 초기값 3으로 입력했습니다. 신규 장소의 점수와 권장 체류시간은 장소 유형에 따른 초기 추정값이며 실제 리뷰 평점이나 공식 평가가 아닙니다. 음식점 세부 분류는 안내 메뉴와 상호를 바탕으로 설정했으며 확인하기 어려운 경우에는 `other-food`로 둡니다. 한식·해산물·양식·중식·일식·간편식·기타 음식점과 카페를 화면 및 추천 점수에서 지원합니다.

## 유명도와 여행 지역

유명도 점수와 평가 방식은 추천 계산에서만 사용하며 사이트 화면의 장소 카드·추천 이유·결과 요약에는 표시하지 않습니다. 유명한 대표 명소와 숨은 장소 중 어느 쪽을 선호하는지 묻는 취향 질문은 유지합니다.

모든 531개 장소의 데이터 파일에 `popularityScore`(1~5)와 `district`를 저장합니다. 유명도는 **초기 편집 평가**이며 방문객 수, 리뷰 수, 검색량을 측정한 통계가 아닙니다.

- 5: 울산 대표 명소(대왕암공원, 태화강국가정원, 간절곶 등).
- 4: 주요 관광 명소 및 기존 큐레이션 음식점·카페.
- 3: 지역 주요 문화·휴식 장소.
- 2: 기타 등록 장소의 초기 기준값. 실제로 덜 유명함이 검증된 것은 아닙니다.
- 1: 개별 기념비·보호수·유적 등 좁은 관심층을 위한 장소의 초기 평가.

대표 명소의 참고 자료: [울산 공식 관광 안내](https://tour.ulsan.go.kr/tour/kor/contents.ulsan?mId=001001004006000000), [울산 12경](https://www.ulsan.go.kr/archive/page/introduce/intro04.do). 개별 장소의 점수는 같은 데이터 파일에서 조정할 수 있습니다.

설문에서 유명한 곳 / 덜 알려진 곳 / 상관없음과 울주군·북구·동구·중구·남구·울산 전체를 선택합니다. 특정 지역은 관광지·음식점·카페 모두에 엄격하게 적용하며 주소로 지역을 확인할 수 없는 장소는 해당 지역 추천에서 제외합니다. 울산 전체는 지역 제한이 없다는 뜻입니다.

지역 값은 `ulju`(울주군), `buk`(북구), `dong`(동구), `jung`(중구), `nam`(남구)이며 미확인은 `null`입니다. 여행 프로필의 `region`은 이 값 또는 `all`을 사용하고, `popularityPreference`는 `famous`, `hidden`, `any` 중 하나입니다. 울산 전체를 선택해도 하루에 모든 구·군을 방문하는 일정이 보장되지는 않습니다.

## 필수 방문 장소 (선택)

설문의 ‘꼭 방문하고 싶은 장소가 있나요?’에서 장소 이름이나 주소로 검색해 관광지·음식점·카페 중 최대 2곳을 선택할 수 있습니다. 선택하지 않으면 기존 취향 추천을 그대로 사용합니다. 선택한 장소는 해제하거나 변경할 수 있고, 위치·체류 정보가 없는 장소는 선택할 수 없습니다.

선택한 순서대로 필수 장소를 먼저 일정에 배치하고, 이동·체류 시간을 확보한 뒤 나머지 관광지를 추가합니다. 음식점과 카페는 관광 동선 주변에서 추천하며, 해당 유형의 필수 장소가 있으면 같은 유형을 자동 추가하지 않습니다. 필수 카페는 휴식 빈도와 관계없이 포함합니다. 필수 음식점·카페는 일반 후보의 거리 제한보다 우선합니다.

선택 지역 밖이거나 지역 미확인인 필수 장소가 있으면 ‘울산 전체’로 변경하거나 선택을 해제하도록 안내합니다. 지역은 사용자가 변경해야 합니다. 필수 장소의 이동·체류만으로 여행 시간이 초과되면 결과 생성을 막고 시간 연장 또는 장소 조정을 안내합니다. 일부 필수 장소를 조용히 누락시키지 않습니다.

필수 장소 ID는 여행 프로필의 `requiredPlaceIds`에 저장하며, 생략하거나 빈 배열이면 필수 방문 조건이 없습니다. 결과의 여행 스타일 요약에서 필수 장소를 확인할 수 있습니다.

장소 카드의 추천 이유는 취향과 장소 특성이 어떻게 맞는지 자연스러운 문장으로 설명합니다. 장소 유형에 관련된 관심사·음식 선호, 동행, 활동량, 휴식 적합도를 응답한 선호의 가중치로 평균한 ‘취향 적합도’를 정수 퍼센트로 표시합니다. 관심사·음식 제한이 없는 항목과 혼자 여행의 동행 항목은 제외합니다. 휴식 필요도는 해당 항목의 중요도로 반영하여 휴식이 적게 필요하다는 이유로 감점하지 않습니다. 유명도와 관광두레 가점은 표시용 적합도에서 제외하며, 이 수치는 AI가 예측한 만족 확률이 아닙니다. 항목별 점수는 표시하지 않으며, 중립값이나 낮은 일치도를 긍정적인 추천 이유로 사용하지 않습니다.

음식점은 음식 선호만으로 표시용 적합도를 계산합니다. 음식 종류가 일치하면 90%, 음식 선호에 제한이 없으면 85%, 종류가 다르면 0%, 미분류 음식점 또는 채식 여부를 확인할 수 없는 경우에는 중립값 50%입니다. 모든 음식점에 공통으로 입력된 활동량·동행·휴식의 초기 점수는 제외합니다. 음식점의 85%·90%는 음식 선호 상태에 따른 표시 기준이며, 실제 만족 확률이나 검증된 예측값이 아닙니다.

## 추천 알고리즘

추천 로직은 [recommendation.ts](src/lib/recommendation.ts)에 구현되어 있습니다.

### 1. 지역 필터와 여행 성향 점수 계산

선택한 구·군에 속한 장소만 후보로 남긴 뒤 점수를 계산합니다. 이 필터는 관광지·음식점·카페 모두에 적용하며, 다른 지역으로 자동 대체하지 않습니다. 필수 장소가 선택 지역과 충돌하면 사용자가 조건을 조정해야 합니다. 울산 전체를 선택하면 지역 필터를 적용하지 않습니다. 좌표가 없거나 유효하지 않은 장소는 경로 추천에서 제외합니다.

| 평가 항목 | 최대 점수 | 반영 기준 |
| --- | --- | --- |
| 관심사 | 25점 | 장소 카테고리와 관심사 일치 여부. 음식점은 음식 선호도 함께 반영 |
| 동행인 | 20점 | 가족·연인·친구 적합도. 혼자 여행은 중립값 적용 |
| 활동량 | 15점 | 선호 활동량과 장소 활동량의 차이 |
| 휴식 | 15점 | 사용자의 휴식 필요도와 장소의 휴식 적합도 |
| 유명도 | 25점 | 유명한 곳 선호는 높은 점수, 숨은 곳 선호는 낮은 점수에 높은 일치도 적용. 상관없음은 중립값 |
| 관광두레 | 추가 8점 | 데이터의 `isTourismDure`가 `true`인 경우 |

기본 점수는 최대 100점이며 관광두레 가점은 별도입니다. 음식 선호는 점수에 반영하는 요소이며 특정 음식점을 반드시 제외하는 필터는 아닙니다. 지원되는 관심사가 없으면 관심사 점수에 중립값을 적용합니다.

### 2. 관광지 선정과 방문 순서 구성

1. 필수 장소가 있으면 먼저 배치하고, 없으면 성향 점수에 취향 적합도 × 0.5를 더한 선정 점수가 가장 높은 관광지부터 시작합니다. 체류·추정 이동시간이 여행 시간 안에 들어오는 관광지를 최대 3개, 여행 시간이 6시간 이상이면 최대 4개 선정합니다.
2. 다음 관광지는 `성향 점수 + 취향 적합도 × 0.5 − 직전 관광지와의 거리(km) × 거리 감점`으로 비교합니다. 거리 감점은 자가용 0.3점/km, 대중교통 1점/km, 도보 3점/km입니다. 유명도 선호 여부와 관계없이 취향 적합도와 이동 부담을 함께 비교합니다.
3. 음식점을 최대 1개 추가하고, 휴식 빈도가 4점 이상이면 카페를 최대 1개 추가합니다. 현재 설문의 휴식 응답은 1·3·5점이므로 ‘자주’를 선택하면 카페 추천 대상이 됩니다.

모든 방문은 이동·체류 시간을 포함해 선택한 종료시간 안에 배정합니다. 최종 결과는 방문 순서로 반환하며, 일정과 지도에서 동일한 순서를 사용합니다. 선택한 지역과 시간에 맞는 관광지가 없으면 빈 일정과 조건 변경 안내를 표시합니다.

### 3. 음식점·카페의 이동 거리 제한

음식점이나 카페만을 위해 멀리 이동하지 않도록, 선정된 관광지 중 한 곳과의 거리 및 일정에 추가되는 우회 거리를 모두 제한합니다.

| 이동수단 | 관광지와의 최대 거리 | 방문 1개 추가 시 우회 거리 상한 |
| --- | --- | --- |
| 자가용 | 3km | 4km |
| 대중교통 | 1km | 1.5km |
| 도보 | 600m | 800m |

현재 설문은 자가용과 대중교통을 제공합니다. 도보 기준은 타입과 추천 로직에 구현되어 있습니다.

첫 관광지 방문 이후의 각 위치를 후보로 비교합니다. 두 장소 사이에 넣는 경우 `이전 장소 → 후보 → 다음 장소`의 거리에서 기존 `이전 장소 → 다음 장소` 거리를 뺀 값을 우회 거리로 계산합니다. 일정 마지막에 넣는 경우에는 마지막 장소에서 후보까지의 편도 거리를 사용합니다.

거리 제한을 통과한 후보는 아래 기준으로 비교합니다.

```text
선정 점수 = 성향 점수 + 취향 적합도 × 0.5 − 20 × (추가 우회 거리 / 이동수단별 우회 거리 상한)
```

음식점을 먼저 삽입한 뒤 변경된 일정에 카페를 삽입합니다. 후보 선정에 사용하는 거리 감점은 원래 성향 점수와 항목별 설명을 변경하지 않습니다. 가까운 후보가 없으면 해당 유형을 생략하며, 관광지가 없으면 음식점·카페만으로 일정을 만들지 않습니다.

점수 가중치는 `RECOMMENDATION_WEIGHTS`, 관광지 개수와 카페 추천 조건은 `RECOMMENDATION_RULES`, 거리 제한은 `FOOD_DISTANCE_LIMITS`에서 확인할 수 있습니다.

## 암각화 여행자 유형

유형검사의 상황 질문 12개는 네 가지 축에 3문항씩 배정되어 있습니다(질문 데이터: [type-test.ts](src/data/type-test.ts)). 축마다 더 많이 고른 쪽의 글자가 유형 코드가 되고, 고른 개수로 추천용 취향 값을 정합니다(계산: [type-test.ts](src/lib/type-test.ts)).

| 축 | 코드 | 추천에 반영되는 취향 |
| --- | --- | --- |
| 여행 에너지 | A 활동 / S 여유 | A 3개 → 활동량 5·휴식 1, 2개 → 활동량 4·휴식 3, 1개 → 활동량 2·휴식 5, 0개 → 활동량 1·휴식 5 |
| 끌리는 무대 | N 자연·바다 / C 문화·역사 | N이 많으면 자연(바다 포함), C가 많으면 문화 관심 |
| 즐기는 방식 | E 체험 / T 맛·풍경 | E가 많으면 체험, T가 많으면 맛집 관심 |
| 가고 싶은 곳 | F 유명 명소 / L 조용한 로컬 | F 3개 → 유명한 곳, F 2개 → 상관없음, L이 많으면 숨은 곳 |

이렇게 만든 취향 값을 기존 `getPetroglyphCode`로 다시 계산해도 같은 유형이 나오도록 맞췄고, 테스트로 16유형 모두 확인합니다. 유형 데이터는 [petroglyph-types.ts](src/data/petroglyph-types.ts)에 있습니다. 동행인은 유형 계산에 사용하지 않습니다. 유형별 추천 코스는 소개 문구이며, 일부 로컬 장소는 아직 추천 장소 데이터에 없습니다.

## 현재 구현 범위와 제한

- 거리는 위도·경도 기반 직선 거리입니다. 실제 도로, 대중교통 노선, 교통 상황은 반영하지 않습니다.
- 관광지는 유명도 취향과 성향 점수, 이동 부담, 여행 시간에 따라 선정합니다. 전체 최단 경로를 보장하지는 않습니다.
- 여행 시작·종료 시간은 관광지 개수 결정과 체류·추정 이동시간 합계 검증에 사용합니다. 출발지에서 첫 장소까지, 마지막 장소에서 귀가하는 이동과 식사 시간대·영업시간은 반영하지 않습니다.
- 음식점·카페 후보가 적어 일부 일정에서는 식사나 카페가 생략될 수 있습니다. 현재 등록된 카페도 관광지와의 거리 제한으로 제외될 수 있습니다.
- 음식 선호의 양식 항목은 양식 카테고리에 반영합니다. 채식 적합성 데이터는 없으며 음식 선호만으로 식단 조건을 보장하지 않습니다.
- 장소 정보와 평가 점수를 실시간으로 검증하거나 갱신하는 기능은 없습니다. 유명도 2점인 기타 장소는 기본값이므로 숨은 명소 여부가 개별 검증된 자료는 아닙니다.
- 지역을 확인할 수 없는 장소는 특정 구·군 추천에서 제외합니다. 울산 전체를 선택해도 좌표가 없는 장소는 경로 추천에서 제외합니다.
